## Object

`VTask.equivIocMod hp a` is a canonical bijection (in fact an equivalence of types) between the quotient group `α ⧸ AddSubgroup.zmultiples p` — whose elements are cosets of the cyclic subgroup generated by `p` — and the half-open interval `(a, a + p]` viewed as a subtype of `α`. Intuitively, it identifies each "residue class modulo `p`" with its unique representative that lies strictly above `a` and at most `a + p`. This is the order-theoretic analogue of choosing a canonical representative in `(0, p]` (or any translate thereof) for an element of the circle `ℝ/pℤ`.

`VTask.equivIocMod : {α : Type u_1} -> [AddCommGroup α] -> [LinearOrder α] -> [IsOrderedAddMonoid α] -> [hα : Archimedean α] -> {p : α} -> (hp : 0 < p) -> (a : α) -> α ⧸ AddSubgroup.zmultiples p ≃ ↑(Set.Ioc a (a + p))`

The implicit type `α` is the ordered Archimedean additive commutative group in which everything takes place (e.g. `ℝ`, `ℤ`, `ℚ`). The typeclass assumptions endow `α` with its additive group structure, a compatible linear order, and the Archimedean property needed to guarantee that every element has a representative in any interval of length `p`. The implicit argument `p` is the period (the modulus). The explicit argument `hp` is the proof that the period is strictly positive, which is essential for the interval `(a, a+p]` to be non-empty and of the correct size. The explicit argument `a` is the left endpoint of the fundamental domain; shifting `a` moves the window of representatives without changing the underlying quotient.

## Conventions

The forward direction of the equivalence maps a coset `[b]` to the unique element of `(a, a+p]` congruent to `b` modulo `p`; this representative is computed by the function `toIocMod hp a`. The inverse direction maps a subtype element `⟨x, hx⟩` (with `x ∈ (a, a+p]`) back to its coset `[x]` in the quotient.

## Worked examples

- Claim: For `α = ℝ`, `p = 1`, `a = 0`, the coset of `0` maps to the subtype element `⟨1, _⟩`, i.e., `VTask.equivIocMod (by norm_num : (0:ℝ) < 1) 0 (0 : ℝ) = ⟨toIocMod (by norm_num) 0 0, _⟩`.

- Claim: For `α = ℝ`, `p = 2`, `a = -1`, the coset of `3.5` maps to the subtype element at `toIocMod (by norm_num : (0:ℝ) < 2) (-1) 3.5`, which equals `1.5`, lying in `(-1, 1]`.

- Claim: For `α = ℤ`, `p = 5`, `a = 0`, the coset of `7 : ℤ` is sent to the element `⟨2, _⟩` since `7 ≡ 2 (mod 5)` and `2 ∈ (0, 5]`.

- Claim: The equivalence `VTask.equivIocMod hp a` is a bijection, so its inverse composed with itself is the identity on `Set.Ioc a (a + p)`; concretely, for any `x ∈ (a, a+p]`, applying the inverse then the forward map returns `x`.

## Boundaries

- When `b = a + p` (the right endpoint), its coset maps to the subtype element `⟨a + p, _⟩`, which is in `(a, a+p]` since `a < a + p` (because `p > 0`) and `a + p ≤ a + p`.
- The left endpoint `a` itself is **not** included in the interval `(a, a+p]`, so no coset maps there; the coset of `a` maps to `a + p` instead.
- The interval `(a, a+p]` is non-empty precisely because `p > 0`, which is why `hp` is required; if `p = 0` were allowed, the codomain would be empty.
- The Archimedean assumption is essential: without it, elements of `α` might not have any representative in a bounded interval, and the representative function `toIocMod` would not be well-defined.

## Not to be confused with

- `toIocMod hp a`: this is the bare function `α → α` that computes the canonical representative; `VTask.equivIocMod` packages it as a proper equivalence (bijection with explicit inverse).
- `QuotientAddGroup.equivIcoMod` (or a hypothetical Ico variant): a similar equivalence using the half-open interval `[a, a+p)` rather than `(a, a+p]`; the choice of open/closed endpoint differs.
- `AddCircle.equivIoc`: in the specialised `AddCircle` type (defined as `α ⧸ AddSubgroup.zmultiples p`), there are related but more structured equivalences that may carry additional topological or measurable-space data.
