## Object

`VTask.ofEq` constructs a realizer for a filter `g` by transporting an existing realizer for a filter `f` along a proof that `f = g`. A *realizer* for a filter is a structured witness that the filter can be described by a basis coming from some index type: it packages an index type `σ`, a basis function `F : σ → Set α`, and a proof that the filter generated by `F` equals the given filter. When two filters are provably equal, any realizer for one immediately yields a realizer for the other, and this function performs that transfer while preserving good definitional behaviour.

## Signature

VTask.ofEq : {α : Type u_1} -> {f g : Filter α} -> (e : f = g) -> (F : f.Realizer) -> g.Realizer

The universe-polymorphic type `α` is the ambient type on which the filters live. `f` and `g` are two filters on `α`. `e` is a proof of equality `f = g`, which is the "bridge" used to transfer the realizer. `F` is the realizer for `f` that is to be transported to produce the result realizer for `g`.

## Conventions

No junk-value or edge-case conventions are declared for this definition: it is a total function on well-typed inputs, its output is a fully determined structure, and there are no boundary inputs (such as default values for out-of-range indices) that require special conventions.

## Worked examples

- Claim: If `e : f = g` is `rfl`, then `VTask.ofEq rfl F` has the same index type `σ` as `F`.

- Claim: If `e : f = g` and `F` is a realizer for `f`, then the realizer produced by `VTask.ofEq e F` carries the same basis function as `F` (i.e., the `F` field of the result equals the `F` field of the input realizer).

- Claim: The realizer produced by `VTask.ofEq e F` generates exactly the filter `g`, as witnessed by combining `F`'s own proof that its basis generates `f` with the equality `e`.

- Claim: When `e` is `rfl` (so `f = g` by reflexivity), `VTask.ofEq rfl F` is definitionally a valid realizer for `f` (= `g`) with the same components as `F`.

## Boundaries

- The only input constraint is that `e : f = g` must be a proof that the two filters are literally equal (as terms). If `f` and `g` are equal only propositionally via some non-`rfl` path, the function still works correctly, but the resulting realizer's `eq` field will be a composition of `F`'s original proof with `e`, rather than `F`'s proof alone.
- When `e` is `rfl`, the output is essentially the same realizer as the input, with no change to any field except the type annotation on the equality proof.
- The function is total: it is defined for every choice of `α`, `f`, `g`, `e`, and `F`.

## Not to be confused with

- `Filter.Realizer` (the structure itself): that is the type being produced here, not the transport operation.
- `Eq.rec` (the general transport along an equality in type theory): `VTask.ofEq` is specifically designed to have better definitional equalities than a naive `Eq.rec` application would give, while achieving the same logical effect.
- Realizer constructors that change the basis or index type: `VTask.ofEq` preserves both `σ` and the basis function `F.F` unchanged; it only updates the equality proof component.
