## Object

`VTask.cycleFactors f` computes, for a permutation `f` of a finite linearly-ordered type, a list of **disjoint cycles** whose product (left-to-right composition in the list) equals `f`. The result is bundled as a Lean subtype: a list `l` together with proofs that (1) `l.prod = f`, (2) every element of `l` is a cycle, and (3) the elements of `l` are pairwise disjoint (move disjoint sets of points). This is the list form of the cycle decomposition theorem for finite permutations.

`VTask.cycleFactors : {α : Type u_2} -> [Fintype α] -> [LinearOrder α] -> (f : Equiv.Perm α) -> { l // l.prod = f ∧ (∀ g ∈ l, g.IsCycle) ∧ List.Pairwise Equiv.Perm.Disjoint l }`

The type `α` is the finite set being permuted; the `Fintype α` instance provides finiteness; the `LinearOrder α` instance is used to fix a canonical ordering of the elements of `α`, which determines the order in which cycles appear in the output list (cycles are generated by scanning elements in ascending order). The argument `f` is the permutation to be factored.

## Conventions

The linear order on `α` determines the ordering of the output list: cycles are listed in the order in which their smallest support element first appears when scanning `α` in ascending order. Fixed points of `f` (elements mapped to themselves) do not appear in any cycle in the list, since the identity permutation is not a cycle.

## Worked examples

- Claim: For the identity permutation on a finite type, `VTask.cycleFactors 1` is witnessed by the empty list, since the identity has no cycles.

- Claim: For a transposition `τ` swapping two distinct elements `a` and `b` in a finite type, `VTask.cycleFactors τ` is witnessed by a singleton list `[τ]`, since a transposition is itself a cycle and is already its own cycle decomposition.

- Claim: For a permutation `f` of `{0,1,2}` that is a 3-cycle (sending 0→1→2→0), `VTask.cycleFactors f` is witnessed by a singleton list containing that 3-cycle, since a cycle is its own cycle decomposition.

- Claim: For a permutation `f` of `{0,1,2,3}` that is the product of two disjoint transpositions (0↔1 and 2↔3), `VTask.cycleFactors f` yields a list of length 2, both entries being cycles, listed in ascending order of their smallest support element.

## Boundaries

- The identity permutation (no element is moved) yields the empty list, since there are no cycles to list. The empty product is the identity, so `[].prod = 1 = id` holds.
- A single cycle `f` that is already a cycle yields a singleton list `[f]`.
- The `LinearOrder` instance is required and affects the *order* of the output list but not its underlying set of cycles; a different linear order would produce the same cycles in a possibly different order.
- Since `IsCycle` excludes the identity permutation, fixed points never contribute entries to the list.
- The underlying *set* of cycles in the list is uniquely determined by `f` (the cycle decomposition is unique), even though the list itself depends on the linear order.

## Not to be confused with

- `Equiv.Perm.cycleFactorsFinset`: the finset-valued version of the same decomposition, which gives the underlying set of cycles without an ordering and without being packaged as a list.
- `Equiv.Perm.cycleOf`: gives a single cycle — the cycle of `f` at a particular point — rather than the full list of all cycles.
- `Equiv.Perm.cycleType`: records only the multiset of support sizes of the cycles, discarding the cycle permutations themselves.
