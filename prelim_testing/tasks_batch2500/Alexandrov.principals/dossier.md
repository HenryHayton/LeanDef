## Object

`VTask.principals` is a functor from a topological space `X` — equipped with a compatible preorder whose open sets are all upper sets (an Alexandrov-type topology) — into the opposite of the lattice of open sets of `X`. It sends each point `x ∈ X` to the *principal open* generated by `x`, i.e., the smallest open set containing `x` (equivalently, the upper set `↑x = {y : X | x ≤ y}`), and sends each inequality `x ≤ y` (viewed as a morphism in the preorder category) to the inclusion morphism `principalOpen y ⊆ principalOpen x` (reversed in the opposite category, reflecting that larger points have smaller principal opens under an upper-set topology).

`(X : Type v) -> [TopologicalSpace X] -> [Preorder X] -> [Topology.IsUpperSet X] -> CategoryTheory.Functor X (TopologicalSpace.Opens X)ᵒᵖ`

The explicit argument `X` is the carrier type of the topological space. The instance `TopologicalSpace X` provides the topology on `X`. The instance `Preorder X` supplies the partial order on `X` that is compatible with the topology. The instance `Topology.IsUpperSet X` is the compatibility condition asserting that every open set of `X` is an upper set with respect to the given order (i.e., `X` carries the Alexandrov topology associated to the order). The return type is the functor category whose source is `X` viewed as a thin category (with a unique morphism `x ⟶ y` iff `x ≤ y`) and whose target is the opposite of the frame of opens of `X`.

## Conventions

There are no junk-value or edge-case conventions to declare: the functor is well-defined for every point of `X` and every morphism (i.e., every inequality) in the preorder, and no sentinel or fallback values are needed.

## Worked examples

- Claim: For any `x : X`, the object part of `VTask.principals X` at `x` equals the opposite of the principal open at `x`, i.e., `(VTask.principals X).obj x = .op (principalOpen x)`.

- Claim: For a morphism `f : x ⟶ y` in `X` (witnessing `x ≤ y`), the morphism `(VTask.principals X).map f` is the opposite of the inclusion `principalOpen y ⊆ principalOpen x`, reflecting that principal opens are contravariant in the point.

- Claim: The composition `VTask.principals X ⋙ P` for a presheaf `P : (Opens X)ᵒᵖ ⥤ C` is exactly the restriction of `P` along the principal-open embedding, and if `P` is the right Kan extension of this restriction then `P` is a sheaf for the Grothendieck topology on `Opens X`.

- Claim: If `x ≤ y` in `X`, then `principalOpen y ⊆ principalOpen x` as open sets, which is exactly what the morphism assigned by `VTask.principals X` to the inequality `x ≤ y` encodes (in the opposite category, this becomes a morphism from `op (principalOpen x)` to `op (principalOpen y)`).

## Boundaries

- When `x` is a minimum element of `X` (i.e., `x ≤ y` for all `y`), `principalOpen x = ⊤` (the whole space), which is the largest open set; `VTask.principals X` maps `x` to `op ⊤`.
- When `x` is a maximum element, `principalOpen x` may be a very small open set (possibly just `{x}` if the order is discrete).
- For a discrete preorder (equality only), each principal open is just a basic open neighbourhood of the corresponding point, and the functor is injective on objects.
- The functor is contravariant on the open-set side: larger points (higher in the order) yield smaller principal opens, which is why the codomain is the *opposite* category.

## Not to be confused with

- `TopologicalSpace.Opens.principalOpen` — this is the single open-set constructor used pointwise by `VTask.principals`; the principals functor packages the whole family into a categorical functor.
- The Yoneda embedding of the preorder `X` — the Yoneda embedding maps `x` to the presheaf of down-sets `(y ↦ y ≤ x)`, whereas `VTask.principals` maps `x` to the open upper set `{y | x ≤ y}`.
- `CategoryTheory.Functor.op` — a general tool for flipping the variance of a functor; `VTask.principals` already produces a functor into the opposite category and should not be confused with applying `.op` to an unrelated functor.
