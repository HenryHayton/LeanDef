## Object

A `Filter.Realizer` for a filter `f` on type `α` is a concrete combinatorial representation of `f`: it pairs an index type `σ` with a `CFilter` structure (a directed family of sets indexed by `σ`) such that the filter generated by those sets equals `f`. `VTask.map` promotes such a realizer: given a function `m : α → β` and a realizer `F` witnessing how the filter `f` is generated, it produces a realizer for the pushforward filter `Filter.map m f` — the filter on `β` whose sets are exactly those whose preimage under `m` lies in `f`. The new realizer uses the same index type `σ` as `F`, but each generating set is replaced by its direct image under `m`.

`VTask.map : {α : Type u_1} -> {β : Type u_2} -> (m : α → β) -> {f : Filter α} -> (F : f.Realizer) -> (Filter.map m f).Realizer`

The implicit type arguments `α` and `β` are the source and target types of the function. `m` is the function used to push the filter forward. The implicit argument `f` is the filter on `α` being realized. `F` is the realizer for `f` — the concrete combinatorial data certifying that `f` is generated by a certain directed family of sets indexed by `F.σ`.

## Conventions

There are no junk-value or edge conventions to declare for this definition: it is a total constructor that is well-defined for every choice of function `m` and realizer `F`, including the identity function, constant functions, or realizers for principal and trivial filters.

## Worked examples

- Claim: Applying `VTask.map` to a realizer for the principal filter `Filter.principal s` with the constant function `fun _ => c` yields a realizer for `Filter.map (fun _ => c) (Filter.principal s)`, which equals `Filter.pure c` (when `s` is nonempty). The realizer's index type is the same as that of the original principal-filter realizer.

- Claim: If `F` is a realizer for the cofinite filter on `ℕ` and `m : ℕ → ℕ` is the doubling map `fun n => 2 * n`, then `VTask.map m F` is a realizer for `Filter.map (fun n => 2 * n) Filter.cofinite`, and the sets generated by this realizer are images under `m` of the cofinite sets.

- Claim: If `F` is a realizer for a filter `f` and `m` is the identity function `id`, then `VTask.map id F` is a realizer for `Filter.map id f`, which equals `f` itself. The realizer's index type and base point are unchanged.

## Boundaries

- When `m` is the identity, the resulting realizer represents a filter equal to `f` itself, since `Filter.map id f = f`.
- When `m` is a constant function `fun _ => b`, the mapped filter is `Filter.pure b` if `f` is non-trivial (i.e., `f ≠ ⊥`), and `⊥` if `f = ⊥`. The realizer is always well-formed regardless.
- When `f = ⊥` (the bottom filter), `Filter.map m ⊥ = ⊥`, and `VTask.map m F` yields a valid realizer for `⊥`.
- The index type `F.σ` of the new realizer is identical to that of the input realizer `F`; no new index type is introduced.
- The definition is total: there are no restrictions on `m`, `f`, or `F`.

## Not to be confused with

- `Filter.map m f` (the pushforward filter itself): `VTask.map` constructs a *realizer* for this filter, not the filter value itself.
- `Filter.Realizer.comap`: the analogous construction for the *pullback* (comap) of a filter along a function, which goes in the opposite direction.
- `CFilter.map` (if it exists): a map operation on the underlying `CFilter` structure alone, without packaging the result into a full `Filter.Realizer` with a membership proof.
