## VTask.kernMap

### Object

`VTask.kernMap m f` is a filter on `β` constructed from a function `m : α → β` and a filter `f` on `α`. Its sets are exactly the *kernel images* of sets belonging to `f`: a set `s ⊆ β` belongs to `VTask.kernMap m f` if and only if there exists a set `t ∈ f` such that `s = kernImage m t`, where `kernImage m t = {b : β | m ⁻¹' {b} ⊆ t}` (equivalently, `s = (m '' tᶜ)ᶜ`). This construction is the right adjoint of the comap filter operation: it stands in the same relation to `Filter.comap` as `Set.kernImage` stands to `Set.preimage`.

`VTask.kernMap : {α : Type u_1} -> {β : Type u_2} -> (m : α → β) -> (f : Filter α) -> Filter β`

The first (explicit) argument `m` is the function from the source type `α` to the target type `β` along which the filter is pushed forward via kernel images. The second explicit argument `f` is the filter on `α` whose sets are transformed. The universe-polymorphic type arguments `α` and `β` are inferred automatically.

### Conventions

There are no special junk-value or edge conventions declared for this definition: the function is total over all functions `m` and all filters `f`, and the filter axioms are satisfied automatically by the construction.

### Worked examples

- Claim: For the principal filter on a set `s`, `VTask.kernMap m (Filter.principal s) = Filter.principal (Set.kernImage m s)`. That is, kernel-mapping a principal filter yields the principal filter on the kernel image of the underlying set.

- Claim: A set `s` belongs to `VTask.kernMap m f` if and only if there exists `t ∈ f` with `Set.kernImage m t = s`.

- Claim: The complement `sᶜ` belongs to `VTask.kernMap m f` if and only if there exists a set `t` whose complement `tᶜ ∈ f` and whose image under `m` equals `s` (i.e., `m '' t = s`).

- Claim: For any filter `g` on `β`, `Filter.comap m g ≤ f` if and only if `g ≤ VTask.kernMap m f`. This expresses that `VTask.kernMap m` is the right adjoint of `Filter.comap m` in the lattice of filters (a Galois connection).

### Boundaries

- When `m` is surjective, `Set.kernImage m t = m '' t` does not generally hold; the kernel image is strictly larger than the image when `m` is not injective, so `VTask.kernMap m f` can be strictly coarser than `Filter.map m f`.
- When `f` is the `⊤` filter (the filter of all sets), `VTask.kernMap m ⊤` is also `⊤`, since `univ ∈ ⊤` and `kernImage m univ = univ`.
- When `f` is the `⊥` filter (the empty filter / the filter containing all sets including `∅`), `VTask.kernMap m ⊥` is also `⊥`, since every set is in `⊥` and hence its kernel image is too.
- The construction is particularly natural for "co-" filters: for instance, `VTask.kernMap m (Filter.cocompact α)` is the filter generated by complements of images `m '' K` where `K` is compact in `α`.
- There is no requirement that `m` be continuous, injective, surjective, or otherwise structured; the definition is purely set-theoretic and works for any function between types.

### Not to be confused with

- `Filter.map m f`: the pushforward filter, where `s ∈ Filter.map m f ↔ m ⁻¹' s ∈ f`; this is the left adjoint of `Filter.comap`, while `VTask.kernMap` is the right adjoint.
- `Filter.comap m g`: the pullback filter along `m`, satisfying `Filter.comap m g ≤ f ↔ g ≤ VTask.kernMap m f`; it maps filters on `β` to filters on `α`, in the opposite direction.
- `Set.kernImage m s`: the underlying set-level operation `{b | m ⁻¹' {b} ⊆ s}` that `VTask.kernMap` lifts to filters; `VTask.kernMap` on a principal filter returns the principal filter of the kernel image.
