## Object

`VTask.liftOn` is the non-dependent recursion principle for the monoid localization `Localization S`. Given a commutative monoid `M` and a submonoid `S`, every element of `Localization S` is represented (non-uniquely) as a fraction `a / b` with numerator `a : M` and denominator `b : S`. This combinator allows one to define a function out of `Localization S` by specifying its value on such pairs `(a, b)`, provided the specification respects the equivalence relation `r S` that identifies pairs representing the same fraction.

`VTask.liftOn : {M : Type u_1} -> [CommMonoid M] -> {S : Submonoid M} -> {p : Sort u} -> (x : Localization S) -> (f : M → ↥S → p) -> (H : ∀ {a c : M} {b d : ↥S}, (Localization.r S) (a, b) (c, d) → f a b = f c d) -> p`

- `M` is the underlying commutative monoid being localized.
- The `CommMonoid M` instance supplies the monoid structure.
- `S` is the submonoid of `M` whose elements are inverted in the localization.
- `p` is the target sort into which the function maps.
- `x` is the element of `Localization S` at which the function is being evaluated.
- `f` is the candidate function defined on numerator–denominator pairs: given a numerator `a : M` and a denominator `b : S`, it returns a value in `p`.
- `H` is the well-definedness hypothesis: whenever two pairs `(a, b)` and `(c, d)` are related by `r S` (i.e., represent the same element of the localization), `f a b` and `f c d` must agree.

## Conventions

There are no declared junk-value or boundary conventions for this definition: it is a total function defined for every element `x : Localization S` provided the well-definedness condition `H` holds, and the target `p` is an arbitrary sort with no imposed structure.

## Worked examples

- Claim: For the localization of `ℕ` at the submonoid generated by `2`, applying `VTask.liftOn` to `mk 3 ⟨2, _⟩` with `f a b := a` (projection to numerator, well-defined when shown compatible) evaluates to `3`.

- Claim: `VTask.liftOn (Localization.mk a b) f H = f a b` for any `a : M`, `b : S`, well-definedness proof `H`, and function `f`. This is the fundamental computation rule: on a canonical representative `mk a b`, the recursion principle reduces to direct application of `f`.

- Claim: If `H` establishes that `f` is constant (i.e., `f a b = k` for all `a`, `b`), then `VTask.liftOn x f H = k` for every `x : Localization S`, regardless of the representative chosen for `x`.

## Boundaries

- The function is well-defined on all of `Localization S` precisely because `H` enforces compatibility with the equivalence relation `r S`; without `H`, two different representatives of the same fraction could yield different values.
- When `x = Localization.mk a b`, the result is definitionally equal to `f a b` (the `liftOn_mk` computation rule).
- The target `p` may be any `Sort`, including `Prop`, allowing this principle to be used for both data and proof extraction.
- The submonoid `S` can be the entire monoid or a trivial submonoid; in both cases the definition applies unchanged.

## Not to be confused with

- `VTask.liftOn₂`: the binary version, which lifts a function of two localization elements simultaneously rather than one.
- `Localization.lift`: lifts a monoid homomorphism out of the localization rather than a bare function on representatives.
- `Localization.rec`: the underlying recursion principle used to implement `VTask.liftOn`; it operates at the level of `Quot` and is lower-level than `VTask.liftOn`.
