**New blocker: a real prompt/parser contract bug**, unrelated to AWS. `authoring/parse.py`'s
`parse_classification` expects `regimes: list[str]` (flat regime-name strings) and crashes with
`TypeError: unhashable type: 'dict'` on `r in REGIMES` when an item isn't a string. The model
returned `regimes` as a list of richer objects (`{type, description, estimated_count}` each) and
omitted `difficulty`/`rationale`/`expected_fact_mix` entirely. Root cause: `classification.txt`'s

schema is spelled out is the file's header comment, which is stripped before sending (by
`authoring/prompt_loader.py`'s own documented behavior) and never reaches the model. Every other
authoring prompt template (`dossier.txt`, `fact_proposal.txt`) DOES restate its schema inside the
sent SYSTEM text; `classification.txt` is the one that doesn't. Not fixed this session (no code
changes made) — see this session's report for the full capture.
